# ADR 0003：新项目根目录与详细架构边界

日期：2026-09-13。状态：首版工程设计采用，算法与运行参数待验证。

前置：[ADR 0002](0002-reconstruction-stack.md)。实现规格：[系统设计](../architecture/01-system-design.md)。

## 决定

1. 项目根目录改为 `D:/Creator-newage`。旧 C++ 原型保留，不在旧目录继续加入新项目代码。现有决策文档复制到新根目录；旧文件不删除。
2. 核心、模型环境、Blender 插件、实验包分离。DA3 独立项目放在根目录 `backends/da3/`，替代早期概览中位于 `reconstruction/backends/` 的拟议位置，避免误当作核心依赖。
3. 核心使用五层职责：入口、应用编排、领域计算、基础设施、外部适配。层是代码依赖约束，不代表五个服务或五个长期运行进程。
4. 首版保留四种任务：`reconstruct`、`refine`、`export_preview`、`evaluate`。它们使用同一作业壳和独立输入类型，不建立通用工作流引擎。
5. `reconstruction/src/creator_recon/contracts/` 中的 Pydantic 2 模型是协议定义源；导出的 `schemas/v1/` 和固定样例是跨环境契约。后端与 Blender 不导入核心模型依赖；消费已发布文件，使用各自的薄读取器。
6. 首版的基础几何是可追溯到照片像素的点记录；研究结果以中心线为主，可辅以点集。管状显示网格是派生预览，不能作为已恢复真实表面的证据。
7. `Refiner.refine(...)` 是唯一需要稳定替换的算法入口。首个候选为 `MultiViewCurveRefiner`；内部采用观测提取、对应、三维拟合与保守接受。尚不认定它具有新颖性或超过现有方法。
8. 基底不可变；补丁必须同时支持抑制旧点与新增几何。一个候选直接绑定一个基础快照。首版不把补丁无限串联，也不把用户在 Blender 中的手工编辑送回算法。
9. 质量评测独立于算法。结构合法、作业完成、用户接受、真实质量提升是四件不同的事，分别记录。

## 为什么保留这些边界

模型版本和恢复算法可能在先导实验中改变；相机、像素、补丁和评测约定不能随之漂移。保持这些接口稳定，才能区分收益来自算法、输入变化还是显示方式。

Blender 内部不安装 PyTorch 等研究依赖。NumPy 版本冲突限制在独立后端环境；基础任务协议不依赖模型的 Python 对象或序列化执行能力。

## 成本与限制

隔离环境增加磁盘产物和进程启动成本，需分开报告冷启动与缓存运行。中心线优先限制了首版可声称的成果，也降低了同时完成曲面、半径、材质、拓扑的风险。

首轮必须验证 Windows 下进程归属、取消、显存释放和 Blender 预览导入。若具体 API 或依赖组合不工作，调整实现机制，并保留协议和可观察行为。

## 改动条件

- 更换基础模型：先实现其真实能力的适配及协议测试；单图模型不能假装拥有多视图相机。
- 更换修复方法：保持输入信息条件、输出语义和评测协议；建立新方法版本与缓存键。
- 引入表面表示：必须同时定义真实半径/表面估计、对应真值和公平评测，不能仅把显示圆管重命名为重建网格。
- 引入 C++、GPU 自定义核或常驻服务：需要性能测量与必要性证据，再单独立项决策。

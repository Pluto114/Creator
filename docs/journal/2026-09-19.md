# 2026-09-19：五张图都同意，也可能一起同意错了

从`951c62d`继续，还是在`D:/Creator-newage`。今天没有回去调旧阈值，而是把9月17日留下的正经问题做成代码：一张图里有好几条亮边时，先都留着，让相机和其他视图一起判断。

先冻了12种情况，开发和评价各6种。里面有干净斜杆、真杆加乱纹、只在三张图可见的杆、稳定的杆内亮条、两条都合理的线，以及空场景里一条跨视图稳定的背景线。RGB、相机和粗guide放输入目录；物理轴和“这里到底有没有目标”单独放评价真值。推理跑完前没读答案。

代码现在会从每张图保留多条受支持的图像线，枚举三视图组合形成三维线，再回所有视图查支持。另有分离候选拿到接近票数时，它返回歧义。以前那种“先在每张图拍板，再假装大家说的是同一根杆”的路子终于被拆开了。

结果一半让人高兴，一半挺扎心。真杆旁边每张图都有不同位置的杂纹时，它能找到正确杆；两条真实一致的线同时出现时，也知道自己不该乱选。但一致的杆内亮条离物理轴7.5厘米，五张图全都支持，算法照样信了。空场景中的一致背景线也拿到五票，被当成假物体。说白了，多视图能证明“这些像素可以由同一条三维线解释”，证明不了“这条线就是用户要的杆轴”。

把门槛从三张抬到四张，能挡住每张图乱跳的空背景条纹；代价是把只在三张图可见、误差只有1.3毫米的真杆也拒了。今天没有选一个看起来数字更漂亮的赢家。三视图太容易凑巧，四视图又会误杀遮挡情况，正确设计应该先判断哪些视图可观测，再把支持数当证据，而不是一刀切。

算法方向因此定下来：多候选关联层保留，它负责排不一致和暴露歧义；最终接受前再加物理身份层，先测试多视图外轮廓/宽度和表面随视角变化的响应。如果一条背景细线在所有输入中真的和目标无法区分，就老实返回歧义或让用户补对应，不编一个自动答案。

完整数字和图见[实验报告](../experiments/2026-09-19-multiview-candidate-association.md)，决定见[ADR 0006](../decisions/0006-multiview-consistency-is-not-identity.md)。今天的12例从现在起只能做回归；下一轮要换新的Blender布局，不能拿看过的评价组继续刷分。

## 下午加速：终于把新 Blender 身份包跑实了

上午的解析包告诉我们“五张图一致也能一起错”，下午就不再拿同一批人造灰条打转，直接写了新的程序化Blender生成器。8种布局、每种5个环绕视角：干净杆、杆面亮条、相邻双杆、中段遮挡、斜杆、强高光、目标加背景杆，以及最要命的“用户目标为空，但ROI里有另一根真实杆”。每帧同步保存RGB、精确相机、evaluated mesh，再用独立射线求相机Z深度、沿射线距离、表面ID和目标可见掩码。输入目录只有RGB、相机和guide，答案继续关在`data/eval_gt`。

生成器第一遍就踩了Blender枚举显示名的坑，第二遍又把3×3和4×4直接乘了。这俩错都发生在首帧前，旧目录保留，分别换运行号继续。更值得记的是`r2`：40张图都生成成功，多视图却8例全拒绝。往下扒才发现拟合器明明支持4×4外参，重投影函数却只支持3×4，而且外层容错把shape异常吃掉了。要是把这种“全拒绝”包装成保守算法就太扯了。修完后补了4×4回归测试，用`r3`整包重跑，终于得到真的算法结果。

`r3`里，干净、遮挡、斜杆和“目标旁边另有背景杆”都正确，p95轴误差约0.37–1.91毫米；杆面亮条、强高光和相邻双杆都保持歧义，没有强行挑真值最近者。空目标那例仍把另一根真实杆当成目标。这个失败其实很值钱：它把“有一根物理线”和“是用户指定的那根”彻底分开了。

我原本想用“更宽候选包住窄亮带”做身份报警，结果新包里它没改变任何判定。亮条案例本来就多解，干净案例又只零星触发。这个想法先降回诊断量，不为了显得今天有新算法就硬塞主流程。

接着做了一个更朴素的粗guide身份门：三维线回投后，至少3个视角且75%视角要落在用户guide附近，容差取原搜索半宽的四分之一。它在已经看过的20例上做开发回放：解析三视图的空目标假物体从3个降到1个，四视图从2个降到1个；新Blender包从1个降到0；所有原本正确接受都保留。坏消息也写死了：离guide很近的表面错误轴仍然通过。guide只能说“用户大概指这儿”，不能说“这就是物理中心”。

40帧又单独跑了一遍哈希、相机、ID、深度和投影轴检查。35个有目标视角、每个101个轴采样点，全部命中目标或声明的遮挡物；目标mask与`surface_id == 1`逐像素一致。图和完整数字见[新报告](../experiments/2026-09-19-blender-identity-and-guide-guard.md)，设计决定见[ADR 0007](../decisions/0007-guide-is-target-identity-input.md)。失败的初始、`r1`、`r2`和正式`r3`都留在D盘，没有拿覆盖旧结果换整洁。

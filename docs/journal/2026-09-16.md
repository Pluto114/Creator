# 2026-09-16：先验证两件小事，别把“看起来像杆”当成证据

接着9月14日的结果往前走。这次不重新跑同一批模型，也不先扩插件；复用原始RGB、已有相机预测和真值隔离链路，把第一版中心定位和逐段检查做出来。

今天先固定两个可被推翻的假设：

1. 一对方向一致、符号相反的边缘，其中点比“哪里亮暗对比最大就选哪里”更接近杆中心。亚像素杆如果边缘分不开，就明确记为不确定。
2. 候选线必须真的投影到各图的杆观测附近；可见位置有明确背景反证时，禁止靠三个视图的散点投票把缺口连上。没有检测到东西，不自动等于背景，更不能等于“应该补一段”。

主实验继续用估计相机，已知相机只作诊断。普通输入里如果相机已经偏了，新的中心定位器不该有本事凭空把它变准；这件事要单独算账。

为减少“拿输入图自我表扬”，另渲染两个之前没用过的角度作保留视图。它们只给评测器，不参与模型、ROI、拟合或阈值选择。这仍是同一个资产的新视角，不能冒充独立对象验证。

参数会在看这轮实测分数前冻结。若实现本身有错误，保留失败记录，修完后对受影响的方法整体重跑；若只是结果不好，先如实记录，不临时把门槛调到好看。

## 先在假数据上摔了一跤

还没打开真值分数，解析测试就找到了规则打架：图像每4行才留一个观测，三维线却要求连续3个采样点有支持。一根完美直杆竟然被切成空。这锅得算在采样设计上，不能推给模型。

处理方式很简单：保留原版作为失败对照，另冻结只改逐行采样的版本。测试里旧版票数是`5,0,5,0…`，新版可保留完整线段。真实数据有没有用，等两版都跑完再看；解析通过不是免检证书。

## 这次实际落了哪些东西

- `rod_observations.py`：从原图找双边缘、中心、宽度和持续性；保留歧义、未知和背景样假设。不会先把缺口涂满再说“拟合挺直”。
- `rod_evidence.py`：固定输入相机，检查投影和留一视图稳定性，再按真正靠近图像观测的位置输出有限段。不同视图投票，重复点不能刷票。拒绝时输出为空，影子候选留下查错。
- `camera_diagnostics.py`：背景匹配残差诊断。目前只记录，不让它擅自挪相机或决定接受。
- 独立拟合/评测脚本、原图K坐标适配检查、完整精简结果表和两张展示图。原模型预测没动，也没重跑DA3。
- 两个新角度、三种条件，共6张仅供验收的渲染。它们没进拟合，也没拿来改阈值。49个文件校验和7872条射线对照通过。

拟合顺序可核对：稀疏版UTC 10:11:44完成，逐行版UTC 10:16:04完成，两版之后才启动评分。全部生产源码、协议和数据身份随run冻结。

## 分数给了一个好消息，也堵住了两条偷懒的路

好消息是：给真实相机时，砖块最细的缺口误覆盖从88.5%掉到0，真杆恢复95.4%。换到未参与拟合的两张图，2px可见召回都是98.3%。原图里确实还有能利用的东西，不是只能对消失的点云干瞪眼。

但先别庆祝过头。新结果还漏了0.165m的真杆长度，不能把“没乱补”当成“全部恢复”。而且这用的是真相机，只能证明局部机制在有利条件下有用。

第一条堵住的路：模型估计相机下8个目标全拒绝。三个504条件的旧结果本来就严重偏位，挡住它们合理；756里却有部分有用的结果也被拒了。所以“有拒绝功能”和“拒绝判断可靠”是两回事，下一轮要把误拒也算进账，不能只展示安全的空输出。

第二条更有意思：中杆在输入图里能自洽，留一视图检查也过了，到了新视角却歪。2px召回两边都是0；放到5px，正角度那张还是0。双边缘不一定就是杆的外轮廓，几张图也可能一起追着错误的亮暗结构跑。下一步先看中心为什么偏，别急着往后面再塞一个更复杂的拟合器。

## 两个没有立功的新模块，也得记账

背景负票开启/关闭，所有候选线段完全一样，没有新增一次有效否决。这轮不能宣称“背景反证解决了缺口”。有效的部分发生在更前面的观测与真实投影支持上。

更要命的是，平坦背景样也可能来自平坦遮挡、低对比杆或分辨率太低的杆。不能在注释里把它偷偷升级成真相。输出里继续标清这是有可观测性前提的假设。

背景ORB检查连真实相机都报不一致，黑白图又没足够特征。砖墙重复纹理可能在骗匹配器，但当前还没逐对应证明原因。这一版诊断不具备直接做相机门控的资格，暂时只记录。避免了另一种“数字很专业，所以肯定有用”。

## 现在决定的下一步

先补中心已知的光照/内部明暗/背景条纹测试，调查中杆的错误边缘对；再把非目标背景匹配做独立几何验证，明确共享相机究竟哪里不可信。继续保留逐行取证、真实缺口、未知和拒绝；新增独立几何布局后冻结验收，不用眼下这一个场景反复调到漂亮。

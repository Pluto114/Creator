# 2026-09-21 开发日志

今天继续G1，先处理昨天最扎眼的问题：几何都对了，怎么还会补错杆？因为“附近有根杆”和“这就是用户要的那根”是两件事。再加一个圆柱公式也猜不出用户的目标。

做了一个很小但实在的输入改动：两张照片各点一下可见目标。点只参与身份选择，不拿来重拟合轴。缺图、缺行、边缘不确定、候选没搜完，都不硬凑答案。代码里把这些判断留下了注释，避免下次为了多出一根杆又把unknown偷偷当通过。

先跑旧开发，再锁方法生成4个新布局、20张严格配对照片。旧560项、新720项，总计1280项回放，包含大量重复窗口、候选上限与点扰动，别把这个大数字写成独立样本数。所有旧输入、失败结果和冻结源码都留着，GT只在评价与事后审计读取。两个正式新增身份运行分别是`rod-foreground-development-v1-20260921`和`rod-foreground-new-queries-v1-20260921`，父场景是`rod-foreground-scenes-v1-20260921`。

好消息：新双杆照片不用换，点A出A、点B出B、混着点不出；普通几何也在另一个布局分别拿到完整杆和两段缺口。这比再做一个好看的预览更接近实际操作了。

打脸的部分也不少。旧开发普通版和圆柱版都是12次正确；新布局普通版13次、圆柱版8次。不能说圆柱白做了，它确实解开了一组双杆歧义，也挡住了一次偏点造成的假杆；但强行把它设成所有输出的总门，会误拒其他真杆。旧遮挡普通版恢复约75.6%，圆柱全拒。新缺口的圆柱轴其实在，第一张标注图却被它退出了几何支持，身份层只能回unknown。不能为了成绩又把这张图偷塞回去。

更要记住：故意两次点错同一根邻杆，圆柱仍4/4误收。新重叠双杆把点各偏4px后，普通版还造出一根约1.966m的中间杆，离请求后杆约112mm；评分后查看ID，两个点都已经在墙上。亮度边缘配出来的带把空隙也包进去了，光说“点在带里面”不够。这次不现场改阈值刷掉坏结果，下一轮明确针对这个假设设计控制。

20,800条独立射线ID零冲突；最大Z误差2.825微米、投影差2.88e-5px。它证明坐标链路，没替RGB抗锯齿背书。源码、协议、图像、有限输出的对应都核过，点击不会移动几何。两张全案例/扰动图已经实际看过。

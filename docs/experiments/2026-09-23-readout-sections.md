# 9月23日冲刺：共同读取器修掉两个盲点，真实模型回放仍不合格

第四版读取器在198个已看过的解析条件中，从189项达标提高到197项。半边表面和局部杂点终于能读到正确杆心，60mm半径在17mm体素下被误拒的6个条件也恢复了。但随后完整回放7份真实DA3输出，仍读出大量背景错线，部分精确率甚至下降。**这轮是明确的局部修复，不能据此宣布共同读取器或G1合格。**

## 改了什么，为什么改

第三版对整块连通点只拟合一次轴，再要求最远点距轴不超过4个体素。这样既把物理半径绑在读取分辨率上，又会被一团局部杂点一票否决。它虽然用圆拟合阻止“半个圆被拆成两根杆”，输出轴仍穿过可见表面的质心；半边表面的质心本来就不是圆心。

新模块`common_readout_sections.py`保留旧文件和全部冻结运行。所有基础点和新增曲线仍先变成相同的体素占据；不读GT半径、GT轴或案例类别。新的分量处理依次做原来的多峰分离，再尝试固定128次、固定随机种子的圆截面一致性拟合：

- 真正用拟合圆心定位轴，避免半边表面质心偏移。
- 用径向残差、至少55%点支持和至少120°角覆盖检查圆截面；允许半径由观测估计，上限相对于轴向长度，不再硬卡4个体素。
- 未解析到圆的小截面保留直线近似。明显连贯、偏离主轴的侧臂单独否决，避免把分支悄悄当杂点删掉。
- 轴向只读实际支持区间，不靠圆柱拟合把长缺口直接接上。

这些都是固定的研究假设，不是经过证明的通用骨架提取器。拟合半径仅辅助读取，未成为物理半径恢复结果。全局直线方向、截面圆假设和连通分量假设仍限制了它的适用范围。

## 提交字节与r2复验

提交前发现新文件的Windows换行与仓库强制LF属性不一致，直接提交会使冻结源码哈希失效。没有加属性例外，也没有覆盖旧运行：保留初轮源码副本、快照和报告，只将新源码、配置、测试规范成LF及一个结尾换行；方法与测试AST完全相同。另建上述两个`20260923r2`运行，重新冻结并完整重跑。

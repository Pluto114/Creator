# DA3 歌剧院点云显示诊断（2026-09-14）

用户截图中，背景像两堵竖墙，歌剧院主体难以辨认。检查发现原网页直接使用 DA3 的相机坐标，第一相机近似 x 向右、y 向下、z 向前；Plotly 默认 z 向上且从斜角观察，因此把远近方向竖着展示。原网页的朝向也与官方导出的 GLB 不一致。

## 实验条件与结论

此前两个演示目录 `20260913T134632.908266Z`、`20260913T135131.043548Z` 都是 BASE、SOH/000.png 和 010.png、长边 504、`use_ray_pose=false`，五组原始数组逐元素相同，并不是 BASE/LARGE 对照。

原 BASE 的反投影再回投到各自相机，最大像素误差约 0.000015，未发现坐标转置或重复取逆错误。原过滤阈值为 1.05，共保留 129,593 / 282,240 个像素对应的点；不是简单保留 60%。输出没有提供天空掩码，不能把截图中的蓝色背景统称为天空。

同一 BASE 点云、相同过滤规则，按相机参数绘制原拍摄方向和偏转 15°的静态图，均可辨认歌剧院，同时仍能看到缺口和边缘误差。诊断图位于 `.runtime/diagnostics/20260914-da3-display/base-view-diagnostic.png`。这说明显示配置是此前难以辨认的主要原因，但不能证明预测几何准确，也没有修复重建。

## 同输入的 BASE / LARGE 实测

| 模型 | 成功推理目录（.runtime/smoke 下） | 输出尺寸 | 峰值 allocated 显存 |
|---|---|---|---|
| BASE | da3-base/20260914T010400.094410Z | 2 × 280 × 504 | 1036.3 MiB |
| LARGE | da3-large/20260914T010448.255947Z | 2 × 280 × 504 | 2746.5 MiB |

两者使用同两张 SOH 图、相同处理分辨率和相机预测选项。LARGE 的偏转预览仍有空洞和边缘问题；本次观察不足以声称它在几何上明显优于 BASE。上述显存仅为本次推理的 PyTorch allocated 统计，不是整个进程占用，也不代表其他照片数量和分辨率。
